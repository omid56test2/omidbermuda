# OMID-IRAN BERMUDA 1.0.1

نسخه خصوصی و خودمیزبان OMID-IRAN با هسته Go، مدیریت فرایند Xray، سه Inbound ثابت به سبک Bermuda، Gateway محدود به مسیرهای اختصاصی کاربران، اشتراک گرافیکی، آمار مصرف، محدودیت‌ها و Backup/Restore.

> این سرویس را فقط روی زیرساختی اجرا کن که قوانین آن صراحتاً استفاده VPN/Proxy را مجاز می‌دانند. این پروژه برای پنهان‌کردن ماهیت سرویس از میزبان یا دورزدن اجرای قوانین طراحی نشده است.

## معماری

- Backend و پنل مدیریتی: Go
- مدیریت فرایند: Xray Supervisor با اعتبارسنجی کانفیگ قبل از اجرا
- Inboundهای ثابت و فقط‌خواندنی:
  - VLESS/XHTTP روی `127.0.0.1:18443`
  - VLESS/WebSocket روی `127.0.0.1:18444`
  - Trojan/WebSocket روی `127.0.0.1:18445`
- Gateway عمومی فقط `/connect/{route-token}` را قبول می‌کند و آن را به Listener داخلی متناظر هدایت می‌کند.
- TLS باید در Gateway یا Reverse Proxy مورداعتماد خاتمه پیدا کند.

## امکانات

- ساخت، ویرایش، فعال/غیرفعال‌سازی و حذف کاربران
- گروه‌بندی اختیاری کاربران
- انتخاب Inboundهای ثابت برای هر کاربر
- حجم، تاریخ انقضا، محدودیت IP، جریان هم‌زمان و سرعت تجمیعی
- Subscription گرافیکی و خروجی Base64 و خام
- QR محلی برای هر کانفیگ
- آمار مصرف با Xray StatsService و اعمال سقف حجم
- مانیتورینگ سیستم و وضعیت Gateway/Xray
- بازیابی خودکار Xray با Backoff
- Backup و Restore محافظت‌شده

صفر برای محدودیت حجم، تاریخ انقضا، تعداد IP، تعداد اتصال و سرعت به معنی نامحدود است. محدودیت XHTTP بر اساس جریان/درخواست هم‌زمان است و تعداد دستگاه فیزیکی را دقیق نمی‌شمارد.

## نصب با Docker

۱. فایل `.env.example` را به `.env` کپی کن.
۲. برای `ADMIN_TOKEN` یک مقدار تصادفی بساز:

```bash
openssl rand -hex 32
```

۳. مقدار `PUBLIC_BASE_URL` را با دامنه عمومی HTTPS خودت جایگزین کن.
۴. برای Reverse Proxy روی همان سرور، `HOST_BIND=127.0.0.1` را نگه دار.
۵. اجرا:

```bash
docker compose --env-file .env -f docker-compose.example.yml up -d --build
```

تصویر Docker شامل باینری رسمی Xray نسخه `26.10.21` است و آن را به‌صورت خودکار اجرا و در صورت خروج غیرمنتظره بازیابی می‌کند. فقط پورت `8080` منتشر می‌شود؛ پورت‌های Listener و StatsService داخل کانتینر روی Loopback می‌مانند.

## بررسی

```bash
./scripts/verify.sh
./scripts/smoke.sh
```

در نسخه 1.0.1 تست‌های Go، بررسی استاتیک، ساخت باینری Linux AMD64 و Smoke Test محلی قابل اجرا هستند. پس از ساخت ایمیج Docker، تست یکپارچه Xray را نیز اجرا کن:

```bash
docker build -t omid-iran-bermuda:1.0.1 .
./scripts/docker-smoke.sh
```

Workflow گیت‌هاب همین تست یکپارچه را برای Linux AMD64 اجرا می‌کند؛ از جمله اعتبارسنجی کانفیگ، اجرای Xray، بازسازی تنظیمات با ایجاد کاربر و خروجی Subscription. این Workflow هنوز در این نشست اجرا نشده است. تست محلی مجوز یا پذیرش سرویس‌دهنده میزبان را تضمین نمی‌کند.

## متغیرهای مهم

- `ADMIN_TOKEN`: توکن مدیر حداقل ۳۲ کاراکتر
- `PUBLIC_BASE_URL`: آدرس HTTPS عمومی برای ساخت لینک کانفیگ
- `XRAY_BIN`: مسیر باینری Xray
- `XRAY_AUTOSTART`: اجرای Xray هنگام راه‌اندازی
- `XRAY_AUTORESTART`: بازیابی خودکار بعد از خروج غیرمنتظره
- `TRUSTED_PROXY_CIDRS`: فقط CIDR پروکسی‌های معتمد واقعی

فایل‌های Backup حاوی رمزها و Route Tokenها هستند؛ آن‌ها را رمزگذاری و خصوصی نگهداری کن. پس از ارتقا از Stage 5، کاربران باید Subscription خود را دوباره دریافت کنند.
